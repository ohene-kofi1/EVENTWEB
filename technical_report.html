Technical Report

1. Introduction and Background

At Kwame Nkrumah University of Science and Technology (KNUST), extracurricular, academic, and professional activities form an essential component of student life. Throughout the academic year, various student associations, academic departments, clubs, and religious ministries organize hundreds of events. These include academic conferences, coding hackathons, annual dinners, sports competitions, night markets, and religious programs.

Despite the high volume of events, publicity and registration mechanisms across the university remain heavily fragmented. Organizers rely on physical paper flyers pasted over campus notice boards, ephemeral WhatsApp status posts, and unstructured broadcast messages in group chats. This absence of a centralized digital directory results in information decay, inaccurate attendance forecasting, venue double-bookings, and lack of verified attendee records.

2. Problem Statement and Objectives

The primary challenge addressed by this project is the lack of a centralized, real-time, and spatially aware platform for university event publicity. Specific challenges include:

  • Information Scattering: Students frequently miss valuable developmental programs due to uncoordinated publicity channels.
  • Geospatial Ambiguity: Freshmen and non-resident students struggle to navigate between distant campus venues (such as the Great Hall, Paa Joe Stadium, College of Science Auditorium, and Prempeh II Library).
  • Capacity and Check-in Inefficiencies: Society organizers lack automated registration caps, resulting in hall overcrowding or unconfirmed turnouts.

Project Objectives: The objective of EVENTWEB is to design and implement an institutional-grade platform that aggregates all campus events into five distinct tracks (Academic, Social, Sports, Religious, Business), provides spatial navigation on an interactive campus map, automates ticket reservation with unique verification codes, and provides verified organizers with an event administration console.

3. System Architecture and Methodology

EVENTWEB is designed following a decoupled, three-tier cloud software architecture consisting of a high-performance presentation client, a managed relational database layer, and a serverless notification engine.

  • Presentation Layer (Frontend): Implemented in semantic HTML5, custom Modernist CSS tokens, and declarative component state logic. It features zero border-radius styling, precise 1px hairline rules, an automated 5-second hero poster carousel with user interaction reset, and a Leaflet.js campus map.
  • Data and Authentication Layer (Supabase): Utilizes a managed PostgreSQL 15 database enforcing relational integrity, custom category ENUMs, JSONB attendance tiers, database trigger functions, and Row-Level Security (RLS) policies.
  • Communication Layer (Resend & Edge Functions): Serverless Deno functions triggered by database insertion webhooks to dispatch branded HTML ticket confirmations and calendar notices.

5. Relational Database Design and Data Integrity

The database schema is normalized into three core relational entities to ensure consistency and eliminate data redundancy:

  • Organizers (`organizers`): Stores verified society and faculty organizer profiles linked directly to Supabase Auth (`auth.users.id`). Fields include `org_name`, `org_type` (Society, Faculty, Club, Committee), `email`, and `is_verified`.
  • Events (`events`): Stores event metadata including title, category ENUM (Academic, Social, Sports, Religious, Business), venue name, date, time, total capacity, registered count, poster image URL, and JSONB attendance options.
  • Registrations (`registrations`): Records individual student ticket reservations. Each row contains a foreign key reference to `events.id`, an optional reference to `user_id`, a unique door check-in reference code (`EW-XXXX-XX`), the selected tier name, and reminder opt-in status.

5.1 Atomic Concurrency Trigger for Capacity Management

To prevent race conditions during concurrent registrations, an atomic PostgreSQL trigger increments `reg_count` on the event table immediately upon valid row insertion: 

CREATE OR REPLACE FUNCTION public.handle_new_registration()
RETURNS trigger AS $$
BEGIN
  UPDATE public.events SET reg_count = reg_count + 1 WHERE id = new.event_id;
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_registration_created
  AFTER INSERT ON public.registrations
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_registration();

5.2 Security and Row-Level Security (RLS)

Row-Level Security is enforced across all tables. Public anonymous users have `SELECT` access only to published events and `INSERT` permissions to register. Organizers are restricted via `auth.uid() = organizer_id` so that they can only modify or view attendance rosters for events they have created.

6. Geospatial Mapping and Campus Venue Coordinates

To assist students in locating event venues across KNUST, EVENTWEB integrates a dedicated Leaflet GIS module mapped to calibrated campus coordinates:

  • Great Hall: 6.67475° N, -1.57220° W (Main Ceremonial Hall and Matriculation/Congregation Auditorium)
  • Paa Joe Stadium: 6.67780° N, -1.56950° W (University Sports Grounds, Marathon Starts, Outdoor Fairs)
  • College of Science Auditorium: 6.67350° N, -1.56650° W (Academic Conferences, STEM Competitions)
  • Prempeh II Library: 6.67510° N, -1.57180° W (Central Academic Resource and Seminar Rooms)
  • KNUST Interdenominational Church: 6.68508° N, -1.57270° W (Religious Fellowships and Services)
  • Central Campus / Brunei Complex: 6.67644° N, -1.57343° W (Night Markets, Fusion Festivals)

The mapping layer uses architectural drafting pins with category-coded color indicators. Selecting an event in the list smoothly pans the map viewport to that venue, while tapping a map marker instantly filters the event roster.

7. User Interface and Interaction Engineering

  • 5-Second Autoplay Rotation: The homepage poster showcase automatically advances to the next flyer every 5000 milliseconds when idle. When the user manually clicks next/previous controls, carousel indicators, or drags a card, the timer resets and restarts a fresh 5-second countdown from that moment.
  • Thin 1px Modernist Hairlines: All interface components (cards, navbar, search input, chips, and modal sheets) utilize a clean 1px hairline rule (`--ew-rule: 1px`). In dark mode, borders shift to `#29324a` to seamlessly blend without harsh glare.
  • Modal Focus Isolation: Opening an event registration sheet automatically suspends background rotations to preserve user concentration while filling out details.

8. Transactional Pass and Reminder Pipeline (Resend)

When a student registers, Supabase triggers a serverless Edge Function running on the Deno runtime. This function calls the Resend REST API to dispatch an immediate confirmation pass containing the event title, flyer thumbnail, society name, date, venue, and unique entry verification code (`EW-XXXX-XX`). API keys are securely stored in server environment variables and never exposed to client browsers.

9. Conclusion

EVENTWEB demonstrates how modern web engineering, geospatial cartography, and cloud database architectures can solve a tangible logistical challenge in tertiary education. By replacing fragmented publicity channels with a unified, aesthetically refined platform, EVENTWEB provides students and student societies with a dependable, scalable, and high-performance event coordination infrastructure.
